# Старославянский переводчик и словарь

Статическое веб-приложение (Vite + чистый JS/CSS), без серверной части, LLM и платных API.
Переводит слова и предложения Старославянский ⇄ Русский, показывает словарную статью с грамматикой.
База (сборка по умолчанию, только источники с понятными правами): около 21 000 статей — старославянских, церковнославянских и древнерусских, из них около 20 000 с русским переводом.

## Возможности

- Две панели с кнопкой смены направления, очисткой и копированием перевода.
- Одно слово: перевод, автодополнение, подробная словарная статья (часть речи, толкование, формы, написания, ударение, родственные слова, греческий оригинал, этимология, пример, источники).
- Предложение: пословный разбор. Найденные слова подсвечены (сплошная линия — точно, пунктир — приблизительно, курсив — только английский перевод), клик по слову открывает его статью. Грамматика не учитывается: слова даются в словарной форме.
- Слова под титлом: `бг҃ъ`, `гд҇ь`, `іс҃ъ`, `чл҃вѣкъ`, `дх҃ъ`, `цр҃ь`, `ап҇лъ`, `бцⷣа` распознаются и раскрываются (`бг҃ъ → богъ`), с титлом и без него.
- Нечёткий поиск: ѣ=е, ѧ/ѩ=я, ѫ=у, ѭ=ю, ѡ=о, і/ѵ=и, ѳ=ф, ѕ=з, ѱ=пс, ѯ=кс, еры отбрасываются, слоговые ръ/рь/лъ учитываются (`слъньце` ~ `солнце`). Можно искать и латиницей: `bogŭ`, `rǫka`.
- Таблицы форм (падеж × число для существительных и прилагательных, лицо × число по временам для глаголов) у около 3 600 слов, из Викисловаря. Нажатие на форму вставляет её в поле ввода, так можно собирать фразу по готовым формам. Автоматического построения форм и согласования пока нет.
- Сворачиваемая клавиатура спецсимволов, переключатель шрифта (стандартный / Monomakh / Ponomar).
- Ссылка с запросом: `…/#q=богъ` (и `&d=ru-cu` для обратного направления).

## Запуск

```bash
npm install
npm run dev
```

Другие команды: `npm run build` (сборка в `dist/`), `npm run preview`, `npm test` (тесты ядра на `node --test`).

## Публикация на GitHub Pages

1. Отправьте проект в ветку `main` репозитория на GitHub.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` на каждый push запускает тесты, собирает проект и публикует `dist/`.

В `vite.config.js` стоит `base: './'`, поэтому сайт работает и на `user.github.io/repo/`, и на своём домене.

## Данные и пайплайн сборки базы

Фронтенд читает готовые файлы из `public/data/` и сам ничего не скачивает:

| Файл | Содержимое |
|---|---|
| `search_index.json` | краткие данные всех статей: слово, часть речи, короткий перевод, формы, язык (около 2,8 МБ, около 0,6 МБ по сети со сжатием) |
| `chunks/ch_XXXX.json` | полные статьи (все значения, примеры, грамматика, источники), по первой букве нормализованной леммы; страница подгружает нужный чанк при открытии карточки |
| `sources.json` | источники, лицензии и число статей от каждого (показывается в подвале сайта) |

Индекс строится в браузере один раз при загрузке (около полусекунды на компьютере), после этого поиск и автодополнение занимают доли миллисекунды.

Пересборка базы:

```bash
python scripts/build_full_dictionary.py
```

Скрипт скачивает источники в `scripts/.cache/` (повторные запуски используют кэш; `--refresh` скачивает заново), разбирает, объединяет по нормализованной лемме и печатает статистику.

По умолчанию источники без явной лицензии (`dyachenko`, `kcs`, `chu-dict`, `chu-gloss`, `pitt-chu`, `pitt-orv`) **не включаются**. Флаг `--with-restricted` добавляет их (около 28 000 статей, но с лицензионным риском для публикации), `--exclude syntacticus` отключает любой источник.

| ID | Источник | Что даёт |
|---|---|---|
| `manual` | `data/curated/dictionary.json` | вручную составленные статьи (имеют приоритет, титла, родственные слова) |
| `dyachenko` | pod-o-mart/lingvo, «Большой церковно-славянский словарь» (Дьяченко) | основной объём русских переводов, ударения |
| `kcs` | pod-o-mart/lingvo, «Краткий церковнославянский словарь» | толкования |
| `chu-dict`, `chu-gloss`, `pitt-chu` | pod-o-mart/lingvo, словари chu–eng | английские значения старославянских слов, формы |
| `pitt-orv` | pod-o-mart/lingvo, древнерусско-русский словарь | древнерусские слова |
| `lexicon` | gold-silver-copper/church-slavonic, только старославянская часть `crates/church-slavonic/lexicon/ocs/*.tsv` | части речи, род, написания |
| `syntacticus` | proiel/syntacticus-dictionaries (`chu.xml`, `orv.xml`) | засвидетельствованные формы, частоты, памятники |
| `ruwikt` | kaikki.org/ruwiktionary, русский Викисловарь: старославянский, церковнославянский, древнерусский | основной объём русских значений, формы, примеры, этимология, связанные слова |
| `kaikki` | kaikki.org, английский Викисловарь, язык `cu` | английские значения, формы, этимология, примеры |

Особенности слияния:
- Статьи объединяются по нормализованной лемме (`богъ`, `бог` и `бг҃ъ` — одна статья), омонимы с одинаковым написанием сливаются. Древнерусские статьи не смешиваются со старославянскими.
- Заглавное написание берётся из самого авторитетного источника (старославянское, с юсами и ятем), остальные написания сохраняются как варианты и участвуют в поиске.
- Порядок в индексе: ручные статьи, затем старославянские (по частоте в корпусе), церковнославянские и древнерусские.
- Файлы `lexicon` и Syntacticus не содержат переводов, поэтому служат только для обогащения статей, у которых перевод есть. Лексемы без перевода (около 1 700 из 7 600) в базу не включаются.
- Словарь Pitt chu–eng записан условной нотацией (основа + класс спряжения), из него берутся только слова, записанные полностью.

## Лицензии источников

Сборка по умолчанию использует только источники с понятными условиями:

- **Русский и английский Викисловарь (Kaikki)** — CC BY-SA 4.0: нужно указывать источник и распространять производные данные на тех же условиях.
- **Syntacticus (PROIEL/TOROT)** — CC BY-NC-SA 3.0/4.0: только некоммерческое использование, на тех же условиях, с указанием авторства. Через него идут формы слов и частоты. Для коммерческого проекта отключите: `--exclude syntacticus`.
- **church-slavonic** — код MIT/Apache-2.0; используется только старославянская часть (`ocs/`), построенная на данных Викисловаря (CC BY-SA 4.0). Церковнославянская часть (`syn/`, Synodal) основана на словаре Полякова: письменное подтверждение прав в репозитории не приложено, поэтому она **не используется** (проверяется тестом).
- **Ручной словарь** — авторская работа проекта.

Итоговая база содержит данные с ShareAlike и NonCommercial, поэтому её нельзя использовать в коммерческих целях без отключения Syntacticus, и её нужно распространять на тех же условиях (CC BY-SA). Список источников с лицензиями показывается на сайте в подвале («Источники и лицензии»).

Источники **без явной лицензии** (включаются только флагом `--with-restricted`):
- словари `pod-o-mart/lingvo` (Дьяченко, КЦС, Pitt и др.): в репозитории лицензия не указана; у КЦС указан источник «© Pagez, 2001–2007». Оригинал словаря Дьяченко (1900) — общественное достояние, но права на его цифровую компиляцию неясны.

Публиковать такую расширенную базу на общедоступном сайте не рекомендуется.

## Структура проекта

```

src/main.js                   связка интерфейса и ядра

```

## Ручной словарь

Формат статьи в `data/curated/dictionary.json`:

```json
{
  "id": "богъ", "headword": "богъ", "pos": "сущ. м.", "ru": ["бог", "божество"],
  "forms": ["боже", "бога"], "titlo": ["бг҃ъ", "бг҃а"], "greek": "θεός",
  "grammar": "…", "gloss": "…", "etymology": "…", "related": ["богородица"],
  "examples": [{ "cu": "…", "ru": "…", "source": "…" }], "note": "…"
}
```

Обязательны `headword`, `pos`, `ru`. Слова из `related` должны существовать в этом файле (проверяет тест). После правки запустите `python scripts/build_full_dictionary.py`.

## Шрифты

Monomakh подключается из Google Fonts. Ponomar Unicode на Google Fonts нет: он используется, если установлен в системе (иначе подставится Monomakh). Чтобы подключить его с сайта, положите файл шрифта в `public/fonts/` и добавьте `@font-face` в `src/style.css`.
